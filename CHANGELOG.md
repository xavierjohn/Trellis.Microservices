# Changelog

All notable changes to this repository will be documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

### Added

- **Documented Azure "Easy Auth" as a gateway front-door actor-provider option** (available since the upstream Trellis `3.0.0-alpha.428` bump below). `trellis-api-yarp.md` now describes registering `AddEasyAuthActorProvider(...)` / `TrellisServiceBuilder.UseEasyAuthActorProvider(...)` (paired with `AddAuthentication(...).AddEasyAuth()`) as the front-door `IActorProvider` when the `Trellis.Yarp` gateway runs behind Azure App Service / Container Apps built-in authentication, including the `X-MS-CLIENT-PRINCIPAL*` trust precondition and the cache `VaryByHeaders` behavior. The cookbook cross-repo deps list and the `trellis-api-yarp.md` "See also" section now name `EasyAuthClaimsActorProvider` alongside `ClaimsActorProvider` / `EntraActorProvider`. Docs-only — the feature lives entirely in upstream `Trellis.Asp` / `Trellis.ServiceDefaults`.
- **Resource-based authorization layer added to the Orders microservice** (`examples/Sample/Orders/`) — wires `Trellis.Mediator` + `IAuthorizeResource<Order>` + `SharedResourceLoaderById<Order, OrderId>` + the v4 `IAuthorizedResource<TCommand, Order>` accessor. Two pre-seeded actors (`john` and `jill`) share the same `orders:read` + `orders:write` permissions but **own different orders** (`order-1` → john, `order-2` → jill). Policy is **view-any (read) + edit-mine (write — owner only)**, encoded in `IAuthorizeResource<Order>.Authorize(actor, order)`. The 8-cell outcome matrix is encoded in `Sample.http` rows 10-17. Billing intentionally stays trust-boundary-only as the counter-example.
- **`orders.resource_loads` counter** — `Sample.Orders` meter exposes a `Counter<long>` tagged with `order.id` that increments inside `InMemoryOrderRepository.FindByIdAsync` (the ACL boundary) on every load. Surfaces in the Aspire dashboard Metrics tab + a structured `OrderResourceLoaded` log line via `[LoggerMessage]` source generator. Since `GetOrderHandler` / `UpdateOrderHandler` inject `IAuthorizedResource<,>` instead of `IOrderRepository`, the counter ticks **exactly once per request** (N curls → N ticks) — falsifiable proof of the v4 typed-accessor load-once invariant. See `ARCHITECTURE.md` §11.5 for the demo (swap to direct `IOrderRepository` injection, observe counter doubling, revert).
- **ARCHITECTURE.md §11 added** — covers resource-based authorization at the microservice (vs gateway) with: a layering diagram (gateway WHO vs microservice WHAT), the actor/resource matrix, the 8-cell outcome table, a sequenceDiagram tracing the full Mediator pipeline showing the SAME-instance handoff between `ResourceAuthorizationBehavior` and `IAuthorizedResource<,>.GetRequiredResource()`, the WRONG-vs-RIGHT handler shape contrast, the metric-based load-once proof, and a code-location index. 3 new Mermaid diagrams added; 11 Mermaid diagrams total in the file (all CLI-validated).
- **Sample-only package pins** in `Directory.Packages.props`: `Mediator.Abstractions` (3.0.2), `Mediator.SourceGenerator` (3.0.2). Added new `Trellis.Mediator` + `Trellis.Primitives` pins at `3.0.0-alpha.360` (these packages were not previously consumed by the sample). Bumped the existing upstream `Trellis.Asp` + `Trellis.Authorization` + `Trellis.Core` + `Trellis.ServiceDefaults` + `Trellis.Testing` pins from `3.0.0-alpha.342` to `3.0.0-alpha.360` to pick up the v4 typed accessor (`IAuthorizedResource<TCommand, TResource>`) which landed in upstream Trellis after `alpha.342`.

### Changed

- **Bumped the upstream Trellis pin from `3.0.0-alpha.425` to `3.0.0-alpha.428`** (single `TrellisVersion` property in `Directory.Packages.props` drives every `Trellis.*` package). The range brings in three upstream PRs: **#667** adds first-class Easy Auth actor support (`AddEasyAuth()` + `EasyAuthClaimsActorProvider` + `AddEasyAuthActorProvider(...)` / `TrellisServiceBuilder.UseEasyAuthActorProvider(...)` in `Trellis.Asp` + `Trellis.ServiceDefaults`) — a candidate gateway front-door actor provider for App Service / Container Apps deployments of `Trellis.Yarp`; **#668** emits exactly one telemetry span per `Trellis.Primitives` value-object factory (not consumed here); **#672** bumps upstream-internal dependencies (Microsoft.Identity.Client, Nerdbank.GitVersioning, Scalar — not consumed here). No consumed public API changed; full build + all 294 tests green on `alpha.428`.
- **Aspire-orchestrated in-repo sample** in `examples/Sample/` — five projects (`Sample.AppHost`, `Sample.ServiceDefaults`, `Gateway`, `Orders`, `Billing`) plus a README walkthrough and a `Sample.http` request runner. One `dotnet run --project Sample.AppHost` boots all three services + the Aspire dashboard at https://localhost:17051. Demonstrates the full Trellis internal-JWT contract: gateway mints a fresh **per-cluster** JWT carrying the full `Actor` surface via `AddDevelopmentActorProvider` + `AddTrellisActorForwarding` + `MapTrellisDiscoveryEndpoint`, **two** downstream services (`Orders` audience=`"orders"`, `Billing` audience=`"billing"`) validate via the Recipe 1 strict `AddJwtBearer` profile + `AddTrellisInternalJwtActorProvider`. Proves YARP path-based routing (`/api/orders/*` vs `/api/billing/*`), per-cluster audience pinning (cross-audience reject as a framework invariant on display), ABAC attribute projection (`tenant_id`), and `RequiredAttributes` fail-closed defense. Gateway uses `AddServiceDiscoveryDestinationResolver` so YARP destinations are `https+http://orders` / `https+http://billing` (resolved by `Microsoft.Extensions.ServiceDiscovery.Yarp` from the env vars Aspire injects via `WithReference`). OTEL traces fan out across services in the dashboard. Distinct from `examples/E2EHarness/` (CI release-gate scenarios) — this is for **reading** to learn the wiring.
- `Microsoft.IdentityModel.Protocols.OpenIdConnect` (8.19.1) pinned in `Directory.Packages.props` to keep the OIDC discovery + JWKS protocol assemblies aligned with `Microsoft.IdentityModel.JsonWebTokens` (8.19.1) and `Microsoft.IdentityModel.Tokens` (8.19.1). Without this third pin, downstream services that wire `AddJwtBearer` against the gateway's `MapTrellisDiscoveryEndpoint` would silently load the JwtBearer-transitive 8.0.1 protocols assembly and fail at request time with `MissingMethodException` masquerading as `IDX14102: Unable to decode the header`.
- Sample-only package pins in `Directory.Packages.props`: `Aspire.Hosting.AppHost` (13.4.2), `Microsoft.Extensions.ServiceDiscovery` + `.Yarp` (10.6.0), `Microsoft.Extensions.Http.Resilience` (10.6.0), `OpenTelemetry.Exporter.OpenTelemetryProtocol` / `.Extensions.Hosting` / `.Instrumentation.AspNetCore` / `.Instrumentation.Http` / `.Instrumentation.Runtime`. Not consumed by packed libraries.
- **E2E release-gate harness** in `examples/E2EHarness/`. 8 scenarios that validate the gateway → JWT → downstream flow end-to-end, plus the consumer-side fail-closed posture against attack tokens (sentinel-stripped, count-mismatched, comma-joined, expected-issuer-mismatched, contract-version-missing). Runs against in-process `TestServer` instances via a custom `IForwarderHttpClientFactory` (no docker, no sockets, < 5 seconds in CI). Maps directly to the P4 invariants in `.github/copilot-instructions.md` "never regress" table. Designed as the gate that release pipelines run before publishing new preview NuGets.

## 0.1-alpha.c — Trellis.Yarp move + Trellis.Microservices.AspNetCore carve-out

### Added

- **`Trellis.Yarp` package** — gateway-side YARP integration MOVED from `xavierjohn/Trellis` (`Trellis.Yarp` package, same NuGet ID, non-breaking move). Re-mints a per-cluster internal JWT from the full Trellis `Actor`, exposes OIDC discovery + JWKS endpoints, emits redacted audit telemetry on every mint. Now depends on `Trellis.Microservices.Abstractions` for the contract claim literals (removed the internal duplicate `TrellisInternalJwtClaimNames.cs` that lived in the package source).
- **`Trellis.Microservices.AspNetCore` package** — consumer-side counterpart CARVED OUT from `xavierjohn/Trellis`'s `Trellis.Asp.Authorization.TrellisInternalJwt*` types. **BREAKING namespace move** for P3 preview-stage adopters: `Trellis.Asp.Authorization` → `Trellis.Microservices.AspNetCore`. Type names unchanged (`TrellisInternalJwtActorProvider`, `TrellisInternalJwtActorOptions`, `TrellisInternalJwtActorOptionsValidator`, `ServiceCollectionExtensions.AddTrellisInternalJwtActorProvider`). Migration: replace `using Trellis.Asp.Authorization;` with `using Trellis.Microservices.AspNetCore;` and add a `Trellis.Microservices.AspNetCore` NuGet reference.
- Tests: 120 from `Trellis.Yarp.Tests` + 84 from `Trellis.Microservices.AspNetCore.Tests` (216 total across all three packages).

### Notes

- Both new packages reference upstream `xavierjohn/Trellis` packages (`Trellis.Authorization`, `Trellis.Core`, `Trellis.Asp`, `Trellis.Testing`) via NuGet at version `3.0.0-alpha.342` — the latest published preview at the time of this release. Future bumps stay in lock-step with upstream releases that change consumed APIs.
- `Trellis.Microservices.AspNetCore.TrellisInternalJwtActorProvider` continues to implement `IProvideActorVaryHeaders` from upstream `Trellis.Asp.Authorization` (the interface stays in upstream). Cross-package dependency is deliberate.

## 0.1-alpha.b — Abstractions package

### Added

- **`Trellis.Microservices.Abstractions` package** — first package in this repo. Ships one public static class `TrellisInternalJwtClaimNames` with the canonical contract literals (`Subject`, `JwtId`, `Permissions`, `ForbiddenPermissions`, `ContractVersion`, `PermissionsCount`, `ForbiddenPermissionsCount`, `CurrentContractVersion = "1"`). Promotes the previously-internal `TrellisInternalJwtClaimNames` (from `xavierjohn/Trellis`'s `Trellis.Yarp`) to `public`, eliminating the duplication where the consumer side (`Trellis.Asp.Authorization.TrellisInternalJwtActorOptions` defaults) hard-coded the same strings by convention. AOT-compatible, no runtime dependencies.
- Tests: `Trellis.Microservices.Abstractions.Tests` — pins every literal value, snapshots the public const surface (catches silent additions / removals), and asserts non-empty + unique values + `IsPublic`/`IsAbstract`/`IsSealed` type modifiers.
